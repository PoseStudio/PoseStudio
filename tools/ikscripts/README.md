# In-app posing scripts

Scripted posing tests that run inside the real application — the picker, the press path, the
camera-parallel drag plane, the 60 Hz solve loop, the release settle, the renderer — and save
what the viewport rendered as PNG files. They exist so that a posing change can be *looked at*,
not only measured: the IK harness (`tools/ikharness`) checks numbers on the armature alone,
and a pose can pass every gate and still look wrong.

Nothing is injected into the operating system. The window's own gesture functions are called
with a scripted cursor, so a run does not touch the mouse or keyboard and is safe on a desktop
that is in use; frames are read back from the GPU, so the window does not need to be visible.
And nothing comes in: while a script runs the viewport ignores real mouse, wheel and key events
and a lost focus (a wheel notch from your own scrolling, the cursor merely over the window, once
dollied the camera under a scripted drag and showed up as a pop that no rerun reproduced; a real
focus change ended the joint mouse mode under a script's `modal` section), and a real Esc pressed
anywhere in the application neither deselects nor leaves VR Mode.

## Running

```
POSESTUDIO_IK_SCRIPT=<script.txt> POSESTUDIO_IK_SCRIPT_OUT=<folder> PoseStudio <figure preset>
```

The app imports the figure, runs the script, writes the shots into the output folder (the
script's own folder when `POSESTUDIO_IK_SCRIPT_OUT` is not set) and exits with the number of
`expect` lines that failed as its exit code (a `shot` no frame came for counts as one; 100 at most;
101 = the script file could not be read, 2 = no figure or model arrived within a minute).
`run.sh` wraps that and builds a
contact sheet; `run_all.sh` runs every script in this folder (not its subfolders) as a test suite:

```
POSESTUDIO_TEST_FIGURE=<figure preset> tools/ikscripts/run.sh tools/ikscripts/gallery_side.txt out/side
POSESTUDIO_TEST_FIGURE=<figure preset> POSESTUDIO_IKSHOTS_REF=<reference folder> tools/ikscripts/run_all.sh out
```

Both need `POSESTUDIO_TEST_FIGURE` (without it they exit 2 and run nothing). `run.sh` runs
`build/Release/PoseStudio.exe` unless `POSESTUDIO_EXE` names another executable, and builds the
sheet with `SHEET_COLS` shots to a row (4) and `SHEET_CROP`, the middle share of each frame's width
kept (0.42; 1 keeps the whole frame).

The output folder is the RUN's own, and a run starts from an empty one: `run.sh` first removes
what an earlier run left there — the shots, `ui/`, `render/`, and everything a script saved
(projects, materials, a texture store) — so that a rerun never reads the last run's files. It
empties only a folder an earlier run made (one that holds a `log.txt`, or the `raw.txt` /
`unfinished.txt` of a run that stopped). A folder that is not empty and is no run's is refused and
left as it is (exit code 102; `run_all.sh` counts that script as failed), and so is one that holds
the figure, the script, the executable, the assets folder or this folder of scripts: keep a
script's inputs in `POSESTUDIO_IK_SCRIPT_ASSETS`, never in the output folder.

`run_all.sh` prints each script's failed expectations and a pass/fail summary (its exit code is
the number of scripts with a failure), and — with `POSESTUDIO_IKSHOTS_REF` — compares every shot
with its reference (`compare.py`): the shots that LOOK different are listed and laid out beside
their references in `<out>/<script>/changes.png`, so after a change there is one image per
script to look at, holding only the poses that moved. (`compare.py` reads the BRIGHTNESS of the
difference: a shot counts as changed when more than 0.2 % of its pixels moved by 24 levels or more,
or its mean difference is over 0.35 — a few levels on a few hundred pixels reads "same". For an
exact comparison, diff the files.) `run_all.sh <out> --accept` makes the run's
shots the new references — after you have looked — for the scripts that passed: a script that
failed an expectation or did not finish is NOT ACCEPTED, its references stay as they were, and its
shots are compared with them as usual. The references are renders of a figure preset: keep them
outside the repository.

## Commands

One command per line; `#` starts a comment; the words are split on spaces. Bones are named as the
reference figure names them (`hip`, `chest`, `head`, `lHand` …); the runner maps them onto the
other generations' names (the alias table the IK harness shares) and, on a rig named in another
convention — an FBX or glTF character — onto the bone with the role the name denotes, so the
same script runs on any figure — set `POSESTUDIO_TEST_FIGURE` to another preset and look.
A line no command takes (an unknown command, too few words, or a `drag` / `wheel` / `release`
with no drag in flight) is logged as `ignored` and changes nothing. `<bone>@<share>` means the point that share of the way
along the bone's limb segment — the flesh, where a user clicks — instead of the joint.

Expectations are regression guards set from what the app does today, with margin — not
specifications. A gesture given in screen metres is only as exact as its guess at the figure's
proportions: where a gate reads looser than the harness's, the gesture is off the joint's arc.

## A scripted run and your preferences

A scripted run is **isolated from the stored preferences**: whatever a script sets — a Preferences page it drives, a tab's switches — serves that run and is never written, and the selection outline and joint highlight start at their default colors whatever you have chosen (the shots are compared with references). `POSESTUDIO_IK_SCRIPT_PREFS=1` makes a scripted run read and write the preferences as any other run does; that is how the storing itself is checked. A scripted run also shows no splash screen (its first mouse press would go to the splash), no What's New window, and no message box for an import that failed (the scripted `import` says `NOT imported` in the log).

## A scripted run opens behind your other windows

A run started on a desktop someone is working at must not jump in front of their work: under `POSESTUDIO_IK_SCRIPT` the main window opens **behind every other window and takes no focus** (its frames are read back from the GPU, so an occluded window serves as well as a visible one). `POSESTUDIO_IK_SCRIPT_FRONT=1` opens it as any other run, to watch a script go.

Do not MINIMIZE it: `shot` waits for the next rendered frame, and a minimized window renders none. After 20 seconds such a shot is given up — `SHOT FAILED: no frame was drawn` in the log, counted in the exit code — and the script goes on (it used to wait for good). If a run reports failed shots, check the window's state before anything else.

## What to look for

The app logs `POP at tick N: <joint> moved X mm in one tick` for every single-tick move over
10cm — never a drag's pace — and `report` names the joint that moved most and when. The POP lines
are in the run's `log.txt`; `run.sh` and `run_all.sh` do not echo them (a passing script may hold
one it knows of), nor the lines of a deliberate refusal (`project NOT opened` where a script
opens a bad file on purpose). `run_all.sh` echoes what fails a script — `EXPECT FAILED`,
`SHOT FAILED`, `DID NOT FINISH` — and the lines that usually mean a script lost its way (a press
that `began no drag`, an `unknown` bone, metric, field or command, a shot `NOT SAVED`); `run.sh`
echoes those and every `report` and `expect` line, what each `click` picked, and the verdict.

A script that does not reach its end (the app went away: a crash, a lost device, a window someone
closed) is reported as DID NOT FINISH with the app's exit code, and the app's whole output is kept
beside the shots as `unfinished.txt`. `run.sh` then never exits 0: the app's own exit code where it
has one, else 101 (a window closed by hand ends the app with 0, which used to read as a pass).


Numbers first (`report`): the grabbed point on the cursor, no unexpected steps, no large
single-tick moves. Then the sheet: balance (is the weight over the feet?), arms and head
(do idle limbs look held or natural?), feet flat, nothing through the floor or the body.
A change that improves a number and makes a sheet look worse is a regression.
